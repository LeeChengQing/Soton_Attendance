# Soton Attendance 系统说明与 Codex 深度评审提示词

> **文档用途：**面向学生、维护者和后续 Codex 评审。说明当前仓库已经实现的功能、学生实际操作方式、系统运行架构、成本与授权边界、已知限制及待核对项。
>
> **代码快照：**本地仓库 main 分支，提交 c54421d（2026-10-01）。正式产品版本标记为 **v1.0.0**；Chrome 扩展内部版本为 **2.4.0**。本文依照仓库代码、现有说明和静态阅读整理；这次没有部署后端、访问商店后台或运行自动化测试，因此不把外部服务运行状态当成已验证事实。

## 1. 一句话说明

Soton Attendance 是一个运行在学生自己 Chrome 浏览器里的自动打卡扩展：学生填写资料、导入并核对课表、绑定并核对 Microsoft Forms 表单后，扩展按马来西亚时间在每节课结束前 5 分钟自动打开表单、填写答案并尝试提交。打卡结果保存在本机，也可以同步到 Supabase；符合授权条件时，云端通过 ntfy 向手机发送明日提醒和打卡结果。

它不是手机 App、学校官方系统或后台无人值守服务。自动操作依赖学生电脑运行、Chrome 打开和学校 Microsoft 账号保持登录。

## 2. 当前完成度一览

| 子系统 | 当前仓库中已有的能力 | 需要留意 |
| --- | --- | --- |
| Chrome 扩展设置页 | 学生资料、课表导入和修改、课程表单绑定、每周任务、打卡记录、手机提醒授权和密钥输入 | 学生数据按 Chrome 用户保存在本机 |
| 课表识别 | JPG/JPEG、PNG、PDF；文字提取和本机英文 OCR；可手动改课程 | 识别结果必须由学生核对；复杂格式可能漏读 |
| Forms 设置 | 读取表单标题和题目，逐题映射学号、姓名、日期、课型、学生身份 | 只支持指定域名和有限题型；表单结构改变会停止自动填写 |
| 单课型试填 | 已有“测试所选课型 · 不提交”按钮；自动填表并显示核对结果 | **没有**整套设置自检记录，也**不会**为这项单表单测试发送手机提醒 |
| 自动打卡 | Chrome 后台按每周任务运行；开始前检查资料、表单和日期；只在明确成功反馈时记录成功 | 电脑休眠或 Chrome 关闭时不能运行；错过后不会补交 |
| 云端与手机提醒 | Supabase 设备 API、课程与绑定同步、打卡日志、提醒队列、ntfy 主题及手机授权服务端检查均有代码 | 生产部署、定时任务、商品和授权密钥库存需要外部运维配置 |
| 付费与激活 | 首学期和续期套餐说明；单次密钥兑换、绑定设备、截止日和服务端授权门槛 | 购买入口目前都指向同一个商店页链接，尚不是两个独立商品直达链接 |
| 完整系统自检 | 本文记录了此前讨论的一键自检需求 | **尚未实现**：逐类试填后确认、独立测试记录、每次汇总推送仍是待开发功能 |

**不要混淆两种版本号：**对学生发布的安装包叫 v1.0.0；扩展清单和 npm 包里的内部版本是 2.4.0。

## 3. 学生能使用的全部功能

### 3.1 安装与浏览器环境

- 支持 Windows 和 macOS 上的 Google Chrome；扩展最低要求 Chrome 120。
- 学生解压 Soton-Auto-Check-v1.0.0-Windows-macOS.zip，在 chrome://extensions 开启开发者模式，再用“加载已解压的扩展程序”加载直接包含 manifest.json 的文件夹。
- 安装后从 Chrome 工具栏的 Attendance 图标打开设置页；学校 Microsoft 账号要在同一个 Chrome 用户中登录。
- Chrome 系统通知用于电脑上的打卡结果提示；手机通知走 ntfy，二者是不同通道。
- 学生不需要安装 Node.js，不需要运行 npm，也不需要 Supabase 账号。

### 3.2 学生资料

设置页第 1 区填写学号、姓名和学生身份（Local Student 或 International Student），然后保存。

这些资料保存在当前 Chrome 用户的本机扩展存储中，用于填写 Forms。源码的云端同步字段不包含学号、姓名或学校登录会话。

### 3.3 导入、核对和修改课表

设置页第 2 区接受 JPG/JPEG、PNG 和 PDF。课表在本机处理：

- PDF 优先读取内嵌文字；没有可用文字时转为图片并使用随扩展打包的英文 OCR。
- 图片课表使用同一套本机 OCR；二维码图片识别也在本机执行。
- 文件限制为 20 MB；PDF 最多 20 页。
- 识别出的课程按星期分组，学生可以展开课程卡片修改课程名称、星期、开始时间、结束时间和停课例外日期，也可以手动添加或删除课程。
- 识别结果包含 Group 1/2 时，学生要删去不属于自己的组别。
- 支持英文星期名称/缩写、常见时段格式和 aSc Timetables 表格布局。日期范围可转换为对应星期后按每周任务处理。
- 识别不完整、扫描模糊或布局不同，都需要学生在创建任务前修正。

课表预览和已创建任务是不同内容：清空第 2 区只清除当前待核对预览，不会删除任务、绑定或打卡记录。

### 3.4 绑定课程二维码或 Microsoft Forms 链接

第 3 区将课程代码与 Forms 表单绑定：

1. 上传二维码截图，或粘贴 Forms 填写链接。
2. 所有课程链接准备好后，点“一键打开全部并核对”；如需登录，先在打开的表单页登录。
3. 核对表单标题、题目和选项，为每一题选择对应资料。
4. 勾选确认后保存绑定。

扩展当前只接受 HTTPS 的 forms.office.com 和 forms.cloud.microsoft 表单填写链接。允许的表单路径和短链接类型有限；不支持的链接、题型或题目映射不能创建自动任务。

目前支持的主要题型：

- 单行文字：学号和姓名等。
- 日期：按题目日期占位格式填入马来西亚当天日期。
- 单选题：Module Delivery 和 Local/International 等选项。

复选框、文本区域、下拉框等未覆盖题型会被拒绝或停止。题目标题、题型或单选项与保存时不同，也会阻止自动填写，避免默默填错。

同一课程代码可共用一个绑定。例如 COMP1311-LEC、COMP1311-TUT、COMP1311-LAB 可对应课程 COMP1311 的同一个 Forms 链接。扩展根据课程名称选择 Lecture、Tutorial 或 Lab/Laboratory；学生身份可以跟随资料或固定选择。若某课程固定课型与课程名不一致，验证会提示修正。

### 3.5 已实现的“不提交”试填

在绑定卡片中点击“测试所选课型 · 不提交”：

- 共用链接时，先在菜单中选择要检查的具体课程/课型。
- 扩展打开对应 Forms 页面，自动填入配置答案并核对填写结果。
- 通过提示显示课程以及识别到的 Module Delivery。
- 学生可以查看页面上的答案；答案之后被手动改动时，原通过提示会撤销。
- 这个测试路径不点击提交按钮，不创建打卡成功记录，也没有单独的系统测试历史或手机提醒。

### 3.6 创建每周自动打卡任务

核对资料、课表和 Forms 绑定后，在第 2 区点击“一键创建每周自动打卡”。

创建前系统会验证学生资料、课程名、时间、例外日期和绑定内容。相同的课程、星期、起止时间不会重复添加；相同课程在不同时间仍是独立任务。

任务每周重复，没有自动的学期起止日期。每节课在**结束前 5 分钟**触发。停课或课程结束后，学生要设置例外日期或删除对应任务。

第 4 区可以逐个删除任务，也可以确认后清空全部每周任务。清空任务会重新构建 Chrome 定时器并同步云端任务，不会清除学生资料、课程绑定或打卡记录。

### 3.7 自动填表、提交与打卡状态

Chrome 扩展后台 Service Worker 通过 chrome.alarms 管理下一次任务，并定期重新计算安排。触发时扩展会：

1. 查找本周任务并生成这一次上课的日期和幂等标识。
2. 检查课程绑定、学号姓名、课程类型及表单配置。
3. 检查任务日期、马来西亚日期和电脑本地日期是否一致。
4. 打开非活动 Forms 标签页，检查当前表单是否与保存的链接、标题和问题结构匹配。
5. 自动填写答案并再次核对实际填写值。
6. 通过核对后才点击 Forms 提交；等待明确的成功页面反馈。
7. 若结果含糊，不自动重试，以免重复提交。

本机打卡记录可显示“打开中、提交中、成功、失败、结果不明、未自动提交”等状态。只有检测到 Forms 明确的成功反馈才显示“成功”。

Chrome 电脑通知用于提醒成功、失败、结果不明或错过时间。自动化不会唤醒电脑、绕过验证码或额外身份验证，也不会自动补交。任务可能受 Chrome 关闭、电脑休眠、学校账号过期、表单不可用或 Microsoft Forms 页面变化影响。学生应按课程规定自行核对出勤，不应把自动化提示视为学校考勤的最终凭据。

### 3.8 ntfy 手机提醒

扩展注册云端设备后会创建随机 ntfy 主题。学生在手机安装 ntfy 并订阅设置页显示的主题，可通过手机接收云端提醒。

当前设计涉及两类提醒：

- 明日课程/自动打卡提醒。
- 自动打卡成功、失败、结果不明或错过时间提醒。

扩展把符合条件的任务与事件写入云端；Supabase 通知 worker 检查授权后，再向 ntfy 发送 HTTP 通知。ntfy 接收成功不等于手机操作系统一定展示了通知，学生还需检查手机的 ntfy 订阅和系统通知权限。

主题地址带有随机值，应当像私密频道凭证一样保管。主题本身不是付费授权，也不能单独让手机收到云端通知。

### 3.9 手机提醒授权、购买和密钥兑换

设置页展示手机提醒授权状态、截止日期、购买入口、密钥输入和刷新按钮。

- 首学期套餐目前显示 ¥12；续期目前显示 ¥5/学期。
- 购买入口需要通过商店自动发货取得密钥，再在当前 Chrome 设备输入并激活。
- 每个密钥只能兑换一次，并绑定到当时的设备。
- 密钥按批次对应学期截止日；截止日按马来西亚时间当天结束计算。同一学期重复兑换不会增加时长，较晚学期续期按服务端规则延长有效期。
- 云端通知 worker 在发送前检查授权是否 active、手机提醒权限是否开启、开始时间是否已到且截止时间未过。未授权设备的队列项目会被丢弃，不发送手机通知。
- 手机提醒授权只控制云端手机推送；本机打卡代码不依赖这项授权。

**价格与运行边界：**界面文案把 ¥12 套餐描述为包含插件使用和首学期手机提醒，¥5 是手机提醒续期；但代码侧真正执行的付费门槛是手机通知的服务端授权。本机打卡不会因未激活而被关闭。按当前界面源码，两个购买按钮都指向同一个临时商店页，正式售卖前应换成各自商品链接。

### 3.10 清空设置的范围

设置页第 2、3、4 区的“清空本区”都会先弹出确认：

| 区域 | 会清空 | 会保留 |
| --- | --- | --- |
| 第 2 区 | 当前待核对课表 | 已创建任务、Forms 绑定、资料、打卡记录 |
| 第 3 区 | 课程二维码/链接及题目映射 | 已创建任务、资料、打卡记录；但任务在重新绑定前无法提交 |
| 第 4 区 | 全部每周任务 | 资料、Forms 绑定、打卡记录 |

## 4. 系统设计与数据流

### 4.1 组件分工

| 组件 | 所在位置 | 职责 |
| --- | --- | --- |
| 设置页 | 学生 Chrome 扩展 | 资料、课表、绑定、任务、记录及手机提醒授权界面 |
| 课表导入器 | 学生本机扩展 | PDF 文字提取、本机 OCR、二维码识别、课表解析 |
| 后台 Service Worker | Chrome 扩展 | 按马来西亚时区重建定时器、启动表单标签页、保存状态和桌面通知 |
| Forms 内容脚本 | Forms 页面 | 检查标题/问题、填入与核对答案、在正式任务通过校验后提交 |
| device-api | Supabase Edge Function | 注册设备、发放 ntfy 主题、任务同步、打卡事件、授权查询和密钥兑换 |
| Supabase Postgres | 云端数据库 | 设备、课程计划、通知偏好、打卡日志、通知队列、密钥和设备授权 |
| send-reminders | Supabase Edge Function | 按明日课程创建手机提醒队列项目 |
| notification-worker | Supabase Edge Function | 检查设备授权，调用 ntfy HTTP 接口发送通知 |
| ntfy 手机 App | 学生手机 | 订阅随机主题，接收已发送的提醒 |
| 维护者密钥工具 | 管理者开发环境 | 生成一组店铺明文库存和一组只含密钥哈希的数据库导入数据 |

### 4.2 自动打卡路径

**Chrome 定时器 → 后台 Service Worker → Forms 标签页 → 内容脚本读取/校验/填写 → 表单提交 → 明确结果写入本机 → 同步 Supabase 日志和通知队列 → 有效授权时由 worker 推送 ntfy。**

课程计划触发点使用 Asia/Kuala_Lumpur。当前代码会在后台启动或安装时重建任务，并每小时做一次维护检查；如果触发点已过去较久，则按错过时间处理，不会无限期补交。对开始提交却没有确认结果的情况，状态记为“结果不明”，不自动重试。

### 4.3 手机提醒路径

**扩展设备注册/任务同步/事件上报 → device-api 验证设备 Bearer Token → Supabase 写入队列 → notification-worker 再查 entitlement → ntfy HTTP → 手机订阅主题。**

主要数据库表：

- devices：设备标识、设备名称、设备令牌哈希和最近活动时间。
- schedules：同步到云端的课程代码、星期、时间、Forms 链接与启用状态。
- attendance_logs：云端打卡事件，每台设备的一次课程日期事件有唯一标识。
- notification_preferences：时区、提醒时间、明日提醒开关和成功通知开关。
- push_subscriptions：ntfy 主题等推送订阅信息。
- notification_outbox：待发送、已发送、失败或因授权不足而丢弃的通知。
- activation_keys：仅保存 SHA-256 密钥哈希、套餐、截止日和兑换状态。
- entitlements：每台设备的授权计划、状态、手机通知权限和有效期。

仓库 README 记载的线上调度约定是：明日提醒每天 UTC 11:30（马来西亚 19:30）创建，通知 worker 每分钟处理待发项目。Edge Function 的代码与权限定义在仓库中，但 Supabase Dashboard 的实际 Cron 配置与线上部署状态不由本仓库证明；上线维护者应以生产 Supabase 项目核实。

### 4.4 设备身份和密钥安全边界

- 扩展首次与云端通信时自动注册设备，保存设备 token 于当前 Chrome 扩展本地存储；后续请求通过 Bearer Token 认证。
- 数据库只保留设备 token 的哈希；扩展端不含 Supabase service-role key。
- 密钥生成工具输出两份文件：商店自动发货使用的明文清单，以及 Supabase 导入使用的哈希清单。明文库存目录在 Git 忽略清单中。
- 密钥由数据库事务兑换并绑定设备；客户端不能自行提交套餐或截止日期来授予权限。
- 设备 token、ntfy 主题和激活密钥都不应公开粘贴到 issue、截图或公共文档里。

## 5. 数据存储与隐私

| 数据 | 主要存储位置 | 是否进入云端 |
| --- | --- | --- |
| 学号、姓名、学生身份 | 当前 Chrome 扩展本机存储 | 当前同步代码不发送 |
| 课表文件原件 | 学生选择的本机文件及浏览器处理过程 | 不上传 |
| 识别后的课程时间/课程名 | 本机任务存储 | 会转换成云端课程计划同步 |
| 已核对的 Forms 链接与映射 | 本机绑定 | 绑定的课程链接会随云端计划同步；题目映射保持本机 |
| 学校 Microsoft 登录状态/密码 | Chrome/学校登录流程 | 扩展不保存、不上传 |
| 打卡状态与错误详情 | 本机记录 | 终态会按事件同步至 Supabase |
| device token 原文 | 当前 Chrome 扩展存储 | 请求时作为凭证传递；服务端数据库保存其哈希 |
| ntfy 主题 | 本机显示并用于订阅 | 服务端作为 ntfy 目标保存 |
| 激活密钥原文 | 购买后由学生短暂输入 | 服务端规范化并哈希，数据库不保存原文 |
| 授权套餐/有效期 | Supabase entitlements | 是 |

扩展目前没有学生账号登录或云端资料恢复界面。因此更换 Chrome 用户、重装为不同扩展 ID/不同安装目录、清除扩展存储或换电脑时，本机资料、课表与表单映射不保证自动迁移。云端保存了部分计划和记录，但当前设置页没有实现从云端完整恢复全部个人配置的流程。

## 6. 学生如何运行

### 第一次安装

1. 解压 Windows/macOS 共用的正式 ZIP，并将文件夹放到不会被随手移动的位置。
2. 打开 Chrome 的 chrome://extensions，打开开发者模式，选择“加载已解压的扩展程序”，指定包含 manifest.json 的文件夹。
3. 用同一 Chrome 用户登录学校 Microsoft 账号，并允许 Chrome 桌面通知。
4. 打开 Attendance 设置页，填写并保存学生资料。
5. 上传课表，逐项校对课程、星期、时间和 Group。
6. 绑定 Forms 二维码或链接，逐题设置映射并保存；每种不同课型至少使用现有试填按钮核对一次。
7. 创建每周任务，并在手机需要云端推送时安装 ntfy、订阅专属主题、购买/兑换有效授权。
8. 让电脑保持运行、Chrome 保持打开、学校账号保持登录。课程变化时更新例外日期或删除旧任务。

### 处理失败

- 先打开扩展第 5 区查看记录状态和错误文字。
- 表单变化/填写值异常：回到第 3 区重新核对标题、题目和映射，再用不提交试填。
- 日期异常：检查电脑日期、时区与马来西亚日期。
- 学校登录失效：在当前 Chrome 用户重新登录后手动确认该次出勤状态。
- “结果不明”：先打开原 Forms 检查是否已经提交；不要要求系统自动重试，以免重复签到。
- 手机没有通知：确认 ntfy 已订阅正确的私人主题、手机和系统允许通知、当前设备授权有效；没有授权时云端不会发送。

## 7. 维护者如何构建、检查和发布

开发者在仓库根目录工作。学生安装时不需要执行本节命令。

依赖安装：

    npm install

运行仓库已定义的 Node 自动化测试：

    npm test

构建 Chrome 扩展，将 src/、依赖和许可证复制/打包进 extension/：

    npm run build

本地模拟 UI、识别和表单行为的浏览器 smoke 流程：

    npm run smoke

密钥纯函数测试：

    deno test supabase/functions/_shared/activation.deno.ts supabase/functions/_shared/entitlement.deno.ts

Supabase 数据库密钥兑换测试需要 Supabase 本地数据库环境：

    supabase test db

构建脚本会重新生成 extension/，但 package.json 当前没有一个用于创建正式 ZIP 的 npm 命令；现有发布 ZIP 是仓库中的构建产物。正式发布前应核对 ZIP 内部版本、Manifest、功能和说明，避免把旧包误当最新包。

生产后端上线还涉及仓库外配置：

1. 在目标 Supabase 项目应用数据库 migration。
2. 安全配置 SUPABASE_URL、SUPABASE_SERVICE_ROLE_KEY 等服务器变量；服务端密钥只放 Supabase，不得写入扩展。
3. 部署 device-api、send-reminders 和 notification-worker。
4. 在 Supabase 生产环境核实授权后的函数调用和定时任务时间。
5. 生成密钥批次后，把明文导入正确的店铺商品库存，把哈希 CSV 导入 Supabase；保管好明文文件。
6. 把代码里的临时购买入口替换成实际首学期/续期各自的商品详情 URL。
7. 使用测试设备验证通知授权和 ntfy 通路，再发布给学生。

仓库只含卖家商品链接和密钥工具，不包含 368FK 支付 API/Webhook，也不会自动建立商品、导入库存或部署 Supabase。

## 8. 当前明确的限制与待修项

以下是本次静态阅读可直接确认的产品缺口或实现问题，交给后续评审时应优先核对：

1. **超时监控存在代码缺陷风险。**当前 src/background.js 的 watchdog() 保存超时记录后，在云端启用时引用了未定义的 status 和 detail 变量。该路径可能抛出异常，导致超时云端上报及后续桌面通知无法执行。应把超时状态正确传入上报并增加回归覆盖。
2. **提醒文案和真实流程不一致。**send-reminders 推送文案写着“请在扩展中确认后才会自动执行”，但当前设置页和后台任务没有明日逐日确认按钮；自动任务按时执行。需统一产品决策和文案。
3. **测试仍然分散。**每门课程需要单独开表单检查；没有一键检查整套设置、完整自检历史或测试提醒。本项目此前讨论过这项升级，目前代码还没有实现。
4. **提醒购买入口未区分商品。**首学期与续期按钮在当前代码里指向同一个商店页；发布前需配置不同商品直达链接。
5. **定时任务配置不随代码交付。**生产 Cron 是否仍按 README 设置运行，要在实际 Supabase 项目核对。
6. **无账号级的配置迁移和恢复。**课程资料与题目映射主要保存在一个 Chrome 安装里；换环境需要重新设置。
7. **课表识别有明确范围。**OCR 只打包英文模型；特殊布局和分组需要人工检查。Forms 页结构变化、登录、验证码或新增题型都可能停住。
8. **本地记录列表仅展示最近 40 条。**云端 API 可以返回最近日志，但当前设置页的列表来自本地扩展存储。
9. **付费边界要在学生端说清楚。**手机提醒需授权；本机自动打卡不受授权拦截。价格、当前购买跳转和实际服务范围不能混为一谈。
