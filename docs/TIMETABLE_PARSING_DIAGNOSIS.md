# aSc Timetables PNG 识别失败诊断

日期：2026-10-05

## 结论

这张 888×627 PNG 的失败发生在**aSc 时间列解析阶段**，不是文件读取或 OCR 完全失败。Tesseract 能读出若干课程代码，也能通过局部重识别读出 Mo/Tu/We/Th/Fr；但表头的 9:00–20:00 被线条和列间距切成多个词、丢冒号或粘上竖线。当前解析器无法构成至少两个有效时间列，因此 `parseASCTimetable()` 返回空数组，普通文本解析也未能补出课程，最后结果为 0 门。

另有两项独立的准确性风险：图中周范围 `5-9/10/26` 不符合日期解析器要求的 `DD/MM-DD/MM/YYYY` 形式；课程后缀、Group、房间号和教师名的小字 OCR 错误很多。即使时间列问题修好，也不应直接把当前 OCR 结果自动启用。

## 1. 当前解析流程（含行号）

1. **入口**：课表上传控件允许 JPG/JPEG/PNG/PDF，见 [src/options.html](../src/options.html#L21)。设置页的 change handler 将文件交给 `importTimetable()`，见 [src/options.js](../src/options.js#L446)。
2. **PNG 路径**：[src/importer.js](../src/importer.js#L90) 判断图片格式后，将原始 `Blob` 用 `createImageBitmap` 画到相同像素尺寸的 Canvas；没有缩放、去线、灰度化、二值化或锐化，见 [src/importer.js](../src/importer.js#L11)。随后 OCR 并调用 `rowsFromPage()`，见 [src/importer.js](../src/importer.js#L29) 和 #L90。
3. **OCR 引擎/模型**：扩展使用 `tesseract.js`，声明版本范围 `^7.0.0`，当前安装版本 **7.0.0**；语言为 `eng`，worker/core/traineddata 静态复制进扩展，见 [package.json](../package.json#L17)、[scripts/build.mjs](../scripts/build.mjs#L17)、[scripts/build.mjs](../scripts/build.mjs#L22)。Tesseract 的默认整页布局模式用于第一次识别，收集每个 word 的 bbox 坐标但生产 importer 丢弃置信度，见 [src/importer.js](../src/importer.js#L29)。
4. **局部重识别**：整图解析没有课程时，如果 OCR 找到类似课程代码的词，就按估算坐标重读标题、表头、星期标签三个矩形，并将输出词框追加回全图结果；局部识别使用 `PSM.SINGLE_BLOCK`，见 [src/importer.js](../src/importer.js#L43) 与 #L47-L63。注意这里不是按每一个表格格子裁切。
5. **aSc 结构解析**：`rowsFromPage()` 同时尝试 aSc 几何解析、常见文本行解析和通用 token 表格解析，合并去重，见 [src/recognition.js](../src/recognition.js#L83)。星期只支持精确 token `mo/tu/we/th/fr/sa/su`，见 [src/recognition.js](../src/recognition.js#L3)。aSc 时间列先找完整时间范围 token；找不到足够范围时，严格要求单独的 `HH:mm` 词、位置相邻且中间有识别到的短横线，见 [src/recognition.js](../src/recognition.js#L26)。至少要有两个列才会继续解析课程，见 [src/recognition.js](../src/recognition.js#L49)。
6. **课程和 Group**：课程词按代码 regex 检出，后缀可作为下方的单独 `-LEC/-LAB/-TUT` token 拼接；Group 标签按课程词上方位置启发式关联，见 [src/recognition.js](../src/recognition.js#L49) 与 #L64-L74。跨节次根据课程词框左右端点映射至最近时间列（同文件 #L45、#L61）。
7. **日期**：标题日期由 `weekDates()` 从 OCR 文本中提取，生成周几到具体日期映射，见 [src/recognition.js](../src/recognition.js#L11)。没有识别出日期时会返回每周课程；识别出日期但未给出某星期时该课程会跳过，见 [src/recognition.js](../src/recognition.js#L75)。
8. **PDF 对比**：PDF 先用 PDF.js 提取文字层及坐标，只有没有解析出课程时才渲染 2 倍分辨率再走 OCR，见 [src/importer.js](../src/importer.js#L70)。当前输入 PNG 没有 PDF 文字层可用。

## 2. 本地图像重放结果

使用新增的只读脚本 [scripts/diagnose-timetable.mjs](../scripts/diagnose-timetable.mjs#L1) 读取用户提供的本地文件，并调用现有 `rowsFromPage()`；OCR 使用当前安装的 Tesseract.js 7.0.0 与同一 `eng/4.0.0_best_int` 模型。PNG 原尺寸 888×627。脚本输出 JSON：每个识别词的文本、`x/y/width/height` 和置信度；分别输出全图及三个局部区域的原始文本；最后列出解析课程与失败阶段。

本次运行结果：

- Full-image OCR 有课程候选，但识别文本混杂。例如表头原文含 `9:00 - 10:00] 10:00 11:00| 1:00 1200 1200 - 1300 ...`；课程行出现 `COMP1313|`、`COMP1312|`、`COMP1300|` 等。
- Retry 的标题区 OCR 为 `CS P1 -W2 (5-9/10/26) S1`；时间头仍将 `1200`、`1300`、`1700`、`1800` 等读成无冒号词，并将第 11 节编号读为 `1"`；星期局部区准确读到 `Mo/Tu/We/Th/Fr`。
- 解析前共有 5 个有效星期标签和 19 个课程样式词框（含局部重试带来的重复）；没有一个完整 `HH:mm-HH:mm` 时间范围词框。精确 clock-word 几何回退仅得 1 列，且是误配 `1:00` 到 `13:00`；解析器要求至少 2 列，因此 aSc 解析立即返回空。
- 通用文本/表格解析也未能从这些拆散的时间和网格内容恢复课程；最终解析列表 `[]`。

可用以下命令重现（只读本地图像，结果写到标准输出）：

```powershell
node scripts/diagnose-timetable.mjs "C:\Users\CQCQ\Downloads\CS-timetable W2.png"
```

如需进度，可先设置 `DIAGNOSE_OCR_PROGRESS=1`；OCR 置信度是 Tesseract 的识别分数，不是课程解析正确率。脚本逐词打印所有识别框，报告中只摘录与失败有关的框。

### 失败原因排序

1. **阻断原因：时间轴词框未解析成至少两列。** 表头字体约 9px，时间范围落在相邻栏边界附近；OCR 将范围拆成 `9:00`、短横线和 `10:00]`，部分冒号丢失，部分词框宽度覆盖相邻 token。`hourColumns()` 的回退需要 exact clock token 与位置上可见的 dash，条件未满足。
2. **识别质量下降：整页单一布局模式遇到密集表格线。** 竖线被 OCR 成 `|` 并粘在课程代码尾部，横线/单元格分隔破坏小字基线；局部三个大区域虽改善了标题和星期，却没有重新识别课程格子，也没有切除表格线。
3. **即使时间轴修好，课程细节仍有错读。** 小字号后缀、Group、房间号/教师文本被识别成其他字符串；当前精确后缀和 Group 正则容易漏配。
4. **日期独立解析不兼容。** 标题中的日期可被 OCR 正确读出，但 `weekDates()` 没有接受 `5-9/10/26` 这种“日-日/月/两位年”的规则。此项本身不会让当前 PNG 变成 0 门（未识别周范围时会退回 weekly），但会丢失日期范围语义；修好后也可能把日期误配到星期。

## 3. 指定难点逐项核对

| 难点 | 是/否与证据 |
|---|---|
| 课程代码与课型拆成 `COMP1313`、`-LEC` 两行 | **是（仅在 OCR 两词均准确且几何满足时）**：当前课程 regex 接受独立代码，后缀规则会在同中心线且下移小于课程词框高度 2.5 倍时拼接，见 [src/recognition.js](../src/recognition.js#L64)。**本图实际否**：Tesseract 输出 `COMP1313|`、`COMP1313.` 和 `“LEC`/`‘LEC`，不符合后缀 exact regex；不过时间轴在其前已阻断解析。 |
| LAB 跨多个节次 | **否（不够稳健）**：没有单元格网格模型；只用课程文字 bbox 的左右端点找最近时间列（[src/recognition.js](../src/recognition.js#L61)）。当文字不铺满合并格、OCR bbox 被裁切或时间列有错时，无法可靠推断真实合并格边界。本图 LAB 词被读作 `COMP1313-LA8`、`COMP1312:0AB`、`COMP1312:0A8` 等，足以导致代码损坏或排除。 |
| 同一 LAB 格内 Group 1/Group 2 上下两层 | **部分**：如果两个课程词框、Group 1/2 标签分别识别正确，当前按标签上方距离和水平范围做关联（[src/recognition.js](../src/recognition.js#L67)）；并未按格子边界配对，邻近多组可能混配。本图 `Group 1` 有时读成 `Gow 1`（约 75/36），Group 2 读成 `Goup2`（约 29）；另一处为 `Grow?`（约 42），所以实际**否**，不能可靠保留两组课程。 |
| 小字体房间号和教师名是否误读 | **是**。全图文本把应为 `3R026`/教师名的小字读成 `ET`（置信度 9）、`CR`（6）、`Ea`（8）、`EE`（47）、`CR`（4）；下一行读成 `Ee`（8）、`ER`（22）、`Ee)`（23）、`ER`（16）、`Ey`（30）。LAB 附属信息另见 `azn`（2）、`sn`（34）、`on`（37）、`som`（50）、`vac`（34）。因此当前 OCR 对这些小字不可信；“老师名字读错”指 OCR 未产出可核对姓名字符串，而不是猜测 `ET/CR` 分别对应哪位老师。 |
| 节次编号 1–11 到时间映射、星期标签 | **否**，代码没有 period 1→09:00、2→10:00 等映射表，只从表头时钟文本和几何位置直接推列，见 [src/recognition.js](../src/recognition.js#L26)。本图编号 1–10 主要识别正确，第 11 读成 `1"`；时间词有 `1:00`、`1200`、`1300` 等错读，造成仅 1 个错误列。**星期局部标签是**：裁切后 `Mo/Tu/We/Th/Fr` 置信度 94–96；全图模式却有单字 `M/W/T` 等，依赖局部重读。 |
| 标题 `CS P1 - W2 (5-9/10/26) S1` 的周范围 | **会误读/漏解析（是）**：局部 OCR 能读到 `5-9/10/26`，但当前 regex 要求起始端也包含月，如 `5/10-9/10/2026`，见 [src/recognition.js](../src/recognition.js#L11)。它不会得到 2026-10-05 至 2026-10-09 的日期映射。 |
| 表格线造成断行或误识别 | **是**：课程 token 尾部出现 `|`，`COMP1312:0AB`/`COMP1312:0A8` 和 `COMP1313-LA8` 表明线条与小字符发生混淆；表头 token bbox 重叠/高度异常，见本次结果中 `9:00` 框 `(110,112,62×9,c=84)` 与 `10:00]` 框 `(144,112,28×9,c=41)`。页面分割也将表格所有行列当单页内容识别，没有依据表格线分割。 |

## 4. 改进方案比较

准确率预期是相对评估，不是对未实现代码的实测百分比。

| 方案 | 改动范围 | 准确率预期 | 风险 | 测试办法 |
|---|---|---|---|---|
| **A. PDF 文字层解析（首选输入来源）** | 引导用户从 aSc 导出 PDF；检查 PDF 是否有文字层。强化 PDF.js token 重组（分行/坐标/合并单元格/日期范围），扫描 PDF 才回落 OCR。现有 PDF 路径已先读文字层，[src/importer.js](../src/importer.js#L70)。 | 如果导出 PDF 保留文字对象和坐标，课程代码、时刻、房间/教师、日期范围预期最高；能消除这张图片的小字号 OCR 主误差。若 PDF 只是 PNG 嵌入则无收益。 | 文字对象可能按单字/字形碎片化；不同 aSc 导出版本坐标结构可能变；要求用户换导出格式。合并格和两组结构仍需布局解析。 | 从相同课表导出 text-based PDF 和 image-only PDF；检查 PDF.js 抽出的 token 是否有真实文本。与人工标注结果比较课程/星期/起止时间/Group 的 precision、recall；image-only 必须走 OCR 回退。 |
| **B. 按格子切分后逐格 OCR** | 对 aSc 栅格模板检测外边框/行列分割线，识别星期行和时间头，再按课程格裁切；对每格去边框/留白/放大，保留合并格跨度；对子行拆 Group 1/2。可能新增表格几何模块及 OCR 数据结构。 | 对固定格式导出预期高于整页 OCR，尤其能隔离短横线、课程和小字号信息；如果保留网格坐标，小字放大后有望改善。 | aSc 样式/页面缩放/边距变化会影响格线；合并格、嵌套横线、Group 分行会令格切分困难；处理照片/倾斜扫描更复杂。 | 生成多种尺寸/压缩质量/轻微倾斜的合成 aSc 表格；标注每格类别、Group、课程、时段；检查切格准确率与课程字段 F1，并加无格线/合并格/空格回归样例。 |
| **C. 预处理加后处理（短期补救）** | OCR 前放大 2–3 倍、灰度/自适应二值化、轻度去水平/竖直线；按课程码/时间/日期/后缀词典修正常见 OCR 混淆；把独立 `COMP...` 和 `-LEC` 行做空间重组；支持 `5-9/10/26` 日期格式；保留 confidence 并对低置信字段要求用户确认。 | 对本图时间冒号、代码尾部竖线和小字可能有中等提升；比按格建模成本低。但 OCR 不懂合并格语义，语法纠错可能改错真实内容。 | 过度二值化会损字；基于代码词典的自动替换可能把真实课程码改错；扩大后仍无法确保房间/教师姓名准确。不可无确认自动启动任务。 | 对同一原图及至少 10 张匿名变体 A/B 比较原图与各预处理版本；记录各字段识别率、置信度校准、误修率；用低置信强制人工核验，并确认不产生静默错时段。 |

**推荐次序**：先优先支持 aSc 原生文字型 PDF（A）作为精度路径；对只能上传 PNG 的用户，再做 B 的“网格/合并格感知”路径。C 作为两条路径共同使用的轻量补充（置信度、有限纠错、日期范围识别），不要把预处理/词典猜测当成唯一修复。对目前 PNG，C 很可能可以提升表头 OCR，但若依赖自动推断，排错风险仍高；用户确认是安全后备。

## 5. 回归夹具计划

当前仓库没有已提交的 aSc 真实课表扫描样例；[scripts/smoke.mjs](../scripts/smoke.mjs#L188) 的现有 PNG/JPG 是一行文字合成图，另外只有通过环境变量可选提供的外部 PDF/JPG 样例（同文件 #L152）。它不覆盖 11 列网格、合并 LAB、上下两组、小字号房间/教师或跨月标题。

建议新增独立 fixture 计划（本阶段不把用户附件复制进仓库）：

1. 用 SVG/绘图脚本生成至少 5 张完全合成的 aSc 风格 PNG：标准课程格、跨 2/3 节合并格、同格 Group 1/2、稀疏空格、边界星期；全用假课程码（如 `TEST1001`）、假房间（`R101`）和虚构教师（`Tutor A`），不写学生姓名/学号/真实教师信息。
2. 从合成向量同时导出文字型 PDF 与栅格扫描 PDF，覆盖文字层方案；PNG 再派生 888×627、缩小/放大、JPEG 压缩、轻微倾斜、灰度、低对比版本，覆盖 OCR 鲁棒性。
3. 每例配一份人工维护的 `expected.json`：课程、星期/日期、开始/结束时间、Group、允许的置信区间和人工确认要求；测试解析字段及负例（错后缀不得 silent-success）。
4. 当前用户附件只留在 Downloads/本机诊断，不提交；若将来确有需要把去标识版本加作 fixture，先确认其无学生个人信息/可识别信息并获得适当同意。仓库提交只放合成图或已获批准去标识图。
5. 先用同一 gold set 比较现有整页 OCR、PDF 文字层、逐格 OCR、预处理+后处理；以完整课程记录准确率及误启用率选型，不只比较 OCR 字符准确率。
